## 二、新发现差距详细分析

### Gap A: 生成的 OpenAPI 类型过时（snake_case）

**实测**：`web/src/generated/models/BacktestResult.ts` 仍为 snake_case：
```typescript
export type BacktestResult = {
    task_id: string;          // 应为 taskId
    strategy_name: string;   // 应为 strategyName
    equity_curve?: Array<any>; // 应为 equityCurve
    benchmark_metrics?: ...   // 应为 benchmarkMetrics
    ...
};
```

**原因**：生成时后端 `backtest.py` 的 `BacktestResult` 仍是 `BaseModel`（无 alias），现已改为 `BaseSchemaModel`（camelCase alias）。生成类型未同步更新。

**影响**：
- 生成类型与实际 API 响应不一致（实际返回 camelCase，类型声明 snake_case）
- 如有开发者引用生成类型会导致类型错误
- 当前前端无代码导入 `generated/`（`grep "from '.*generated'"` 零匹配），所以暂无运行时影响

**附加发现**：生成的 `OpenAPI.ts` 中 `TOKEN: undefined`、`BASE: ''`，即生成服务未配置 JWT 认证，无法直接使用。

### Gap B: 生成类型未被前端采用

**实测**：`web/src/generated/` 含 38 个文件（services/ + models/ + core/），但全前端无任何 import 引用。

**现状评估**：前端使用手写 API 层（`web/src/api/*.ts` + `client.ts` axios）+ 手写类型（`web/src/types/index.ts`），功能完整。生成服务采用独立的 `CancelablePromise` + `request()` 机制，与现有 axios client 不兼容，且未配置 JWT。

**决策**：**不在本次范围内采用生成服务**。保持生成类型作为基础设施，待未来整体迁移时启用。理由：当前手写 API 层工作正常，强制迁移收益小风险大。

### Gap C: mypy 未配置

**实测**：无 `mypy.ini`、`setup.cfg`、`pyproject.toml`。

**决策**：**跳过 mypy**。CI（`.github/workflows/ci.yml`）使用 `ruff check` 而非 mypy，项目从未配置 mypy。v2 计划 Task 9 提及 mypy 但非项目既有流程。

### Gap D: 全量测试验证未完成

**实测**：
- `npm run build`：✅ 通过（含 tsc --noEmit 类型检查）
- `pytest tests/test_api.py tests/test_comparison_agent.py`：✅ 44 passed
- 全量 `pytest tests/`：未执行（共 40+ 测试文件）
- `ruff check stockquant/`：未执行（CI 必需）
- `npm run test`（vitest）：未执行

## 三、修复任务（按优先级排序）

### P0 — 修复过时的生成类型

#### Task A1: 重新生成 OpenAPI 类型

**目标**：使 `web/src/generated/` 反映当前 camelCase 后端 schema

**前置条件**：后端可启动（需能访问 `http://localhost:8000/openapi.json`）

**步骤**：
1. 启动后端服务（`uvicorn stockquant.api.main:app --host localhost --port 8000`），等待就绪
2. 在 `web/` 目录运行 `npm run generate-api`
3. 验证 `web/src/generated/models/BacktestResult.ts` 已变为 camelCase（`taskId`、`strategyName`、`equityCurve`）
4. 停止后端

**验证**：
- 生成类型中关键模型字段为 camelCase
- `npm run build` 仍通过（生成类型不被引用，但需确保不引入编译错误）

**回退方案**：若后端无法启动或生成失败，删除 `web/src/generated/` 目录避免误导（codegen 基础设施保留在 package.json，可随时重新生成）

### P1 — 全量验证

#### Task B1: 后端 ruff lint + 全量 pytest

**目标**：确保 camelCase 迁移未引入回归

**命令**：
```bash
# ruff lint（CI 必需）
ruff check stockquant/

# 全量后端测试
pytest tests/ -v --tb=short
```

**预期**：
- ruff：可能有小问题（unused import 等），修复即可
- pytest：大部分应通过；若有因 camelCase 迁移导致的断言失败，修复测试

**重点关注**：
- `test_api.py` — 已验证 44 passed
- `test_persistence.py` / `test_persistence_100.py` — 数据库相关，可能涉及 schema 变更
- `test_notifier_router.py`、`test_pipeline.py` — 内部方法测试，应不受影响

#### Task B2: 前端构建 + 测试

**目标**：确认前端无回归

**命令**：
```bash
cd web
npm run build    # tsc --noEmit + vite build
npm run test     # vitest run
```

**预期**：
- build：已验证通过
- test：检查 mock 数据是否已全部 camelCase（上个会话已更新测试文件，需确认 vitest 全通过）

### P2 — 清理（可选，视验证结果）

#### Task C1: 修复验证中发现的失败

**条件**：仅当 Task B1/B2 发现失败时执行

**范围**：根据实际失败情况修复，不预设改动
