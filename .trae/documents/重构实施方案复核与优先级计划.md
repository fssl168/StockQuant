## 二、未完成项详细分析

### 2.1 Phase 5 残留：路由层未切换到 repository_v2

**现状**：21 个路由文件中，全部通过 `from stockquant.persistence.repository import xxx` 调用函数式 API，没有使用 `repository_v2.py` 的 `Repository` 类。

**影响**：`repository.py`（100+ 函数）和 `repository_v2.py`（Repository 类）并存，数据访问入口未统一。

**关键文件**：
- `stockquant/persistence/repository.py` — 旧函数式入口（仍在用）
- `stockquant/persistence/repository_v2.py` — 新 Repository 类（已建但未被路由使用）
- `stockquant/persistence/persistent_store.py` — 已标 DEPRECATED，内部委托 repository.py

### 2.2 Phase 6 残留：PendingOrder 未删除

**现状**：
- `models.py:461` — `class PendingOrder(Base)` 仍存在
- `repository.py:1085-1167` — `save_pending_order`/`list_pending_orders`/`delete_pending_order` 仍存在
- `persistent_store.py:38-40` — 仍导入 `save_pending_order` 等
- 无 Alembic 迁移脚本删除 `pending_orders` 表
- Order 表已扩展（`broker_order_id`、`filled_quantity`、`avg_fill_price` 已有）

### 2.3 Phase 7 残留：路由未接入新服务层

**现状**：
- 仅 `monitor.py` 和 `trading.py` 引用了 `DataService`
- **没有任何路由引用 `AIService`** — AI 相关路由（ai_chat、hallucination、pipeline）仍直接构造 `LLMAdapter`
- `portfolio.py` 引用了 `repository.Repository`（但只是别名导入）

### 2.4 Phase 8 残留：前端完全未改造

**现状**：
- `web/src/api/client.ts` — 仍有 `snakeToCamel()` 运行时转换（第 6-25 行）
- 无 `openapi-typescript-codegen` 依赖
- 无 `web/src/generated/` 目录
- `stockquant/api/schemas.py` — 无 `alias=` / `populate_by_name` 配置
- 8 个 Zustand stores 仍手动维护类型

## 三、优先级排序与任务计划

按 **风险消除优先 > 架构统一 > 前端优化** 原则排序：

### P0 — 消除架构冗余（立即执行）

#### Task 1: 删除 PendingOrder 模型及相关代码
**文件**：
- `stockquant/persistence/models.py` — 删除 `PendingOrder` 类（第 461 行起）
- `stockquant/persistence/repository.py` — 删除 `save_pending_order`/`list_pending_orders`/`delete_pending_order`（第 1085-1167 行）
- `stockquant/persistence/persistent_store.py` — 删除 `save_pending_order` 等导入（第 38-40 行）
- 新增 `migrations/versions/004_drop_pending_orders.py` — Alembic 迁移标记 `pending_orders` 表为 deprecated

**验证**：`pytest tests/ -v` 全部通过

#### Task 2: 路由层接入 AIService
**目标**：AI 相关路由从直接构造 `LLMAdapter` 改为通过 `AIService` 获取 LLM 能力

**文件**：
- `stockquant/api/routers/ai_chat.py` — 改为 `from stockquant.ai.service import AIService`
- `stockquant/api/routers/hallucination.py` — 同上
- `stockquant/api/routers/pipeline.py` — 同上
- `stockquant/ai/orchestrator.py` — 改为通过 `AIService` 获取 adapter
- `stockquant/ai/chat_agent.py` — 同上

**验证**：AI 对话页功能正常，反幻觉管线正常运行

### P1 — 统一数据访问入口（短期执行）

#### Task 3: 路由层逐步切换到 repository_v2.Repository
**目标**：21 个路由从 `repository.py` 函数式调用迁移到 `repository_v2.Repository` 类方法

**策略**：分批迁移，每批 3-5 个路由
- **批次 1**：auth、strategy、backtest（核心 CRUD）
- **批次 2**：trading、portfolio、audit（交易相关）
- **批次 3**：ai_chat、memory、hallucination（AI 相关）
- **批次 4**：data、monitor、pipeline、scheduler、notification、settings、optimize、comparison、signal、dashboard

**文件**：`stockquant/api/routers/` 下全部 21 个路由文件

**验证**：每批迁移后运行 `pytest tests/test_api.py -v`

#### Task 4: persistent_store.py 彻底清理
**前置条件**：Task 3 完成后

**文件**：
- `stockquant/persistence/persistent_store.py` — 删除文件或仅保留空壳 + DeprecationWarning
- 搜索全项目 `from stockquant.persistence.persistent_store` 引用并替换

**验证**：`grep -r "persistent_store" stockquant/` 无业务引用

### P2 — 前端类型现代化（中期执行）

#### Task 5: 引入 openapi-typescript-codegen
**文件**：
- `web/package.json` — 添加 `openapi-typescript-codegen` devDependency
- `web/openapi-config.json` — 新建配置文件
- `web/src/generated/` — 新建目录（自动生成类型）
- `web/src/types/index.ts` — 保留前端特有类型，删除与后端重复的类型

**验证**：`npm run generate-api` 成功生成类型文件

#### Task 6: 后端 Pydantic schema 添加 camelCase alias
**文件**：
- `stockquant/api/schemas.py` — 所有 Pydantic Model 添加 `alias=` + `ConfigDict(populate_by_name=True)`

**验证**：`/openapi.json` 中 schema 属性名为 camelCase

#### Task 7: 前端删除 snakeToCamel 运行时转换
**前置条件**：Task 5、Task 6 完成后

**文件**：
- `web/src/api/client.ts` — 删除 `snakeToCamel()` 函数，响应拦截器直接返回 `r.data`
- `web/src/stores/*.ts` — 8 个 store 字段名适配为 camelCase
- `web/src/pages/*.tsx` — 17 个页面字段名适配
- `web/src/components/**/*.tsx` — 26 个组件字段名适配

**验证**：`npm run build` 无类型错误，`npm run test` 全部通过

### P3 — 数据库迁移与测试（收尾）

#### Task 8: Alembic 迁移脚本
**文件**：
- `migrations/versions/004_drop_pending_orders.py` — 标记 pending_orders deprecated
- `migrations/versions/005_jsonb_migration.py` — PostgreSQL JSONB 迁移（metrics/equity_curve）
- `migrations/versions/006_add_indexes.py` — 复合索引（orders: user_id+status，positions: user_id+symbol）

**验证**：`alembic upgrade head` 成功

#### Task 9: 全量测试验证
**命令**：
```bash

mypy stockquant/
pytest tests/ -v --coverage

# 前端
cd web && npm run build && npm run test
```

## 四、假设与决策

| 决策 | 选择 | 理由 |
|------|------|------|
| repository_v2 是否完全替代 repository.py？ | 渐进迁移，保留 repository.py 兼容层 | 避免一次性全量替换风险 |
| PendingOrder 直接删除还是标记废弃？ | 删除代码 + Alembic 标记表 deprecated | 方案明确要求删除 |
| 前端 OpenAPI 生成用哪个工具？ | openapi-typescript-codegen | 方案指定 |
| snakeToCamel 何时删除？ | Task 6 (后端 alias) 完成后 | 确保后端已返回 camelCase |
| 路由迁移批次大小？ | 每批 3-5 个 | 平衡速度与风险 |
